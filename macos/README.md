# DanceForge macOS source

This preserves the existing native app that preceded the RIG website. Its
current app name, bundle identifier, and version remain DanceForge 1.0.2.
The website and native app have separate entry points and account flows.

## Build and offline checks

Requires macOS 14 or later and Xcode Command Line Tools. No package download or
API key is needed to compile or run the checks.

```sh
./macos/test.sh
./macos/build.sh
```

The app is created at `macos/.build/release/DanceForge.app` with an ad-hoc
signature for local use. This is not a notarized distribution build. The build
uses the current machine's architecture; `MACOS_ARCH=arm64` or
`MACOS_ARCH=x86_64` can be set for compilation on a compatible SDK. Run tests
using the host architecture.

The standalone tests compile only `FalClient.swift` and its injected
`URLProtocol` mocks. They cover pricing, request construction, queue state,
credential and URL handling, cancellation, and transfer behavior. They do not
launch the app, access Keychain, upload media, or spend fal credits. CI builds
the complete app but does not launch it.

## Native app behavior

Using the app itself requires the user's own fal account and key. Credentials
are stored in macOS Keychain. The preserved app can discover media in Desktop
and the known local renderer folders; on startup it can import an existing
`FAL_KEY` from the legacy local renderer `.env` when no Keychain credential is
present. Those runtime files and their contents are not part of this source.

## Source provenance

Imported on 7 November 2026 from the active `work/DanceForge` working folder of
the 3 November macOS app session. All seven `Sources/*.swift` files, the existing
`Tests/FalClientTests.swift`, `AppIcon.icns`, and `make-icon.swift` were copied
byte-for-byte from that active source. The older `source-deliverable` snapshot
was not used. The latest active UI/client files were modified on 5 November.

The import adds portable build and offline-test wrappers and CI configuration;
it does not alter those Swift files. Generated app bundles, module caches,
credentials, user media, and personal assets were excluded. The public app icon
is generated by `make-icon.swift` from an SF Symbol and contains no user photo.
